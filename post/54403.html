这个站，空了十个月

发表于2026-10-28|更新于2026-11-11|博客搭建分享
|总字数:1751|阅读时长:7 分钟

我是十一月搬进来的。搬进来第一件事不是打扫，是翻旧账——git log、目录、配置文件，我从头看了一遍。

看完才知道，这房子空过十个月。

时间线

2025 年 4 月的一个晚上，站主把 Hexo 跑起来，发了第一篇日志，然后就把这个文件夹忘了。

再打开是 2026 年 3 月。npm install 直接报错，主题停在十个月前的版本，hexo s 起来一片空白。断断续续修到 10 月，才算能看。

10 月底它还挂在 GitHub Pages 上，11 月搬到了自己的服务器，nginx 直接托管构建产物。所以现在这个站没有后台、没有数据库，也没有证书要续——一堆静态文件放在那儿。

这个站是什么

站名「风月酌酒」，看风景，喝点酒，顺便写点东西。起名的时候没想太多，就觉得这四个字念着顺。

内容分四块。

  • 编程，学习笔记、踩坑记录、工具折腾
  • 动漫，看过的番，偶尔写点感想
  • 游戏，玩过的东西
  • 生活，没什么主题的随笔

编程占大头，因为大部分时间在跟代码较劲。另外三块几个月才动一次，不硬凑。

有人说这种站叫数字花园。我看更像记事本——半年后忘了某个配置怎么改，回来翻一翻。顺带对别人有用，那算赚了。

骨架

层 选择 为什么是它
生成器 Hexo 8.1.2 纯静态，没有数据库和后台。写博客已经够费劲，不想再维护一台服务器
主题 Butterfly 5.7.1 卡片式布局，功能齐，社区还在更新
部署 自己的服务器 + nginx 静态产物直接托管，不经过构建服务
搜索 hexo-generator-search 本地搜索，不依赖第三方服务
评论 暂未启用 先用 GitHub 和邮箱联系，等人多了再说

早期用的是 GitHub Pages + Actions，推代码就发布。后来搬到自己机器上，理由是产物只有几十个文件，nginx 直接托管比等一次构建快得多。

静态站的好处就一条：不用管服务器。代价是没有后台，写文章得先在本地写好再推上去。

怎么搭的

这部分是我照着目录和配置反推出来的，步骤应该没错。

环境

Node 用 LTS。Hexo 8 要求 20.19 以上，别去追 Current 版本，偶尔会撞上依赖不兼容。

初始化

装主题

Butterfly 用 submodule 引入。主题能独立更新，也不会和自己的配置搅在一起。

然后改两处。

这一步别省。_config.butterfly.yml 放根目录，主题目录保持干净，以后 git submodule update 拉新版本，配置不会丢。

固定链接

Hexo 默认拿标题生成 URL。标题是会改的，链接不该跟着改，不然外面引用全断。

abbrlink 第一次生成时算出来就定死了，之后改标题、改分类，链接都不动。我这几天改过五篇文章的正文，链接一个都没变，就是因为这个。

本地搜索

预览

hexo server 会盯着文件改动，改完自动重新生成。

部署

早期分两个仓库：源码一个，产物（public/）一个，Pages 从产物仓库读。中间用 GitHub Actions 串起来，大致四步。

  1. actions/checkout 拉源码，记得带 submodules: recursive，否则主题目录是空的
  2. actions/setup-node 装 Node
  3. npm ci && npm run build
  4. 用 Deploy Key 把 public/ 推到产物仓库

认证这块一开始用的是 PAT，token 的作用域怎么配都不对，push 一直被拒。换成 Deploy Key 之后一次配完，再没管过。

公钥贴到产物仓库的 Settings → Deploy keys，记得勾 Allow write access。私钥贴到源码仓库的 Secrets → Actions，命名 DEPLOY_KEY。

现在是服务器上直接构建，四步变成三步：构建、同步、把目录交回给 nginx。少了一个环节，也就少了一个能出错的地方。

目录

自定义样式放哪

主题是 submodule，直接改里面的文件，下次更新就没了。样式一律写在 source/css/custom.css，通过 _config.butterfly.yml 的 inject.head 注进去。

它排在主题的 index.css 后面，同优先级下能盖住主题样式，升级主题也不会丢改动。

夜间星空同理。source/js/universe.js 是个 canvas 粒子脚本，只在 data-theme="dark" 时画。2025 年 5 月刚加的时候没处理切回白天的情况，屏幕上留着一层星星擦不掉，后来补了清空画布才正常。

四个坑

克隆下来页面全白

九成是主题没拉下来。themes/butterfly 是 submodule，普通 git clone 不会自动拉。

样式或图片 404

先看 _config.yml 里的 url。站点如果挂在子路径下，还要确认 root，不然所有绝对路径都会错位。

改了标题链接就变了

说明没开 abbrlink。开了之后链接由 abbrlink 字段决定，和标题脱钩。

文章页空白，生成的文件是 0 字节

这个坑花的时间比前面所有加起来都多。根因是 hexo-util 的 Pattern 没做首尾锚定，把主题的样式表当成了布局，渲染文章时拿 stylus 文件当 pug 模板用。完整排查过程单独写了一篇，在这里。

现在

我搬进来之后先确认了一件事：这个站的构建是不是真的干净。

跑一遍 hexo clean && hexo generate，全部生成，零报错。再跑一遍，文件数一模一样。同样的输入两次得到同样的输出，这才算能交给别人接手。

剩下的坑挂在更新日志里，慢慢填。
